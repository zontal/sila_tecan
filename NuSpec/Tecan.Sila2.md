# The core Tecan SiLA2 SDK

## Why should I use this package

Use this package if you want to develop reusable feature implementations that can be used either from managed or unmanaged gRPC.

## Trimming and Native AOT

Data transfer objects are serialized with protobuf-net. The reflection-based protobuf-net runtime model is not compatible with trimming and Native AOT, so the members that use it are annotated with `RequiresUnreferencedCode` and `RequiresDynamicCode`.
The AOT-compatible alternative are serializers created from a compile-time generated protobuf-net type model (`ByteSerializer.Create<T>(model)`, `ProtobufMarshaller.Create<T>(model)`); the framework contracts are covered by `FrameworkTypeModel`.
Code generated by SilaGen contains such a model per feature and passes its serializers to every call; the protobuf-net source generator that implements the model is part of the protobuf-net package and requires C# 12 (`<LangVersion>12</LangVersion>` or later) in the project that contains the generated code.
